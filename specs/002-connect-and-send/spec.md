# Spec 002 — Connect & Send (원터치 주문 전송)

- **상태**: 완료 — 2026-08-23 실기기 검증됨 (핸드셰이크 즉시 응답, 탐색 5.2s / 핸드셰이크 5.5s)
- **관련**: [spec 001](../001-ble-scanner-mvp/spec.md), [PEER_CONTRACT.md](../../PEER_CONTRACT.md) §4

## 목적 (Why)

상대(`ble-advertiser`)의 GATT 서버는 **광고 시작 후 60초**면 내려간다. 현재 흐름은 이 창을
사람의 조작 속도로 소모한다:

| 단계 | 소요 |
|---|---|
| 스캔 1사이클 (`discover` 5s + sleep 1s) | ~6초 |
| 목록에서 찾아 Connect 클릭 | 사람 |
| 연결 + GATT 전수 탐색 | ~8초 |
| 메시지 입력 | 사람 |
| Send 클릭 | 사람 |

2026-08-23 실기기 로그에서 이 창을 놓쳐 `Unreachable`로 실패했다. 전송까지를 **한 동작**으로
묶으면 사람의 조작이 창 안에서 사라지고, 남는 건 기계 시간뿐이다.

## 사용자 스토리

1. 운영자는 주문번호를 **미리 입력**해두고, 폰에서 "결제 시작"을 누른 뒤 Connect 한 번만
   클릭하면 연결·핸드셰이크·주문 전송·응답 확인까지 자동으로 끝난다.
2. 운영자는 각 단계가 **몇 초 걸렸는지** 로그에서 보고, 60초 예산 중 얼마를 썼는지 안다.
3. 운영자는 자동 전송을 **끄고** 기존처럼 연결만 할 수 있다.
4. 중간 단계가 실패하면 뒤 단계를 시도하지 않고, 어디서 끊겼는지 명확히 안다.

## 기능 요구사항

- **FR-1 원터치 흐름**: Connect 클릭 시 `연결 → GATT 탐색 → AT+CONNECT → 응답 Read →
  주문 write → 응답 Read`를 중단 없이 수행한다.
- **FR-2 자동 전송 조건**: 메시지 입력란이 **비어있지 않고** 자동 전송 스위치가 켜져 있을 때만
  주문을 보낸다. 비어있으면 연결까지만 하고 멈춘다 (의도치 않은 주문 방지).
- **FR-3 스위치**: `Auto Send on Connect` 스위치를 제공한다. 기본값 ON.
- **FR-4 단계별 소요 시간**: 각 단계와 전체 소요를 초 단위로 로그에 남긴다.
  전체가 60초를 넘으면 경고를 남긴다.
- **FR-5 실패 시 중단**: 어느 단계든 실패하면 이후 단계를 건너뛰고, 실패 지점을 로그에 남긴다.
- **FR-6 수동 Send 유지**: 기존 Send 버튼은 그대로 동작한다 (재전송·추가 전송용).
- **FR-7 스캔 지연 단축**: 스캔 사이클을 줄여 발견까지의 시간을 줄인다.

## 비기능 요구사항

- constitution §1 준수: 전 과정 비동기, UI 프리징 없음.
- constitution §5 준수: 각 단계 예외 처리, 실패해도 UI 상태가 거짓말하지 않을 것.
- 자동 전송이 진행 중인 동안 중복 Send가 큐에 쌓이지 않을 것 (기존 `io_busy` 가드 재사용).
- 상대의 1회 전송 제약(PEER_CONTRACT §4)은 그대로다 — 자동 전송은 **연결당 1회**.

## 완료 기준 (Acceptance)

- [ ] 메시지를 입력해두고 Connect만 눌러도 주문이 전달되고 `Order received` 응답이 로그에 뜬다.
- [x] 메시지가 비어있으면 연결까지만 되고 아무것도 전송되지 않는다.
- [ ] 스위치를 끄면 자동 전송이 일어나지 않는다.
- [x] 로그에 각 단계 소요 시간과 전체 소요가 찍힌다.
- [ ] 핸드셰이크가 실패하면 주문 write를 시도하지 않는다.
- [ ] 자동 전송 중 Send를 눌러도 큐에 쌓이지 않는다.

## 범위 밖

- 자동 재연결 (T12d, 별건).
- 상대의 "주문 1건 후 서버 종료" 제약 해소 — Android 쪽 변경이 필요하다.
- 주문번호 자동 생성 — 세 앱 모두 사람이 입력하는 현행 유지.
